Test GenAI Dashboards With Synthetic LLM Calls

Token, cost, latency and quality signals — and the failures you need alerts for — before real traffic exists.

LLM applications have their own failure modes — runaway token costs, slow first tokens, hallucination, prompt injection — and the observability for them is new enough that dashboards are often built before there is real traffic to build them on. OTel Studio's AI Observability simulator produces that traffic on demand, using the OpenTelemetry GenAI conventions.

What it simulates

LLM calls across eight models from five providers (OpenAI, Anthropic, Google, DeepSeek and xAI), balanced rather than weighted to one provider. Each call emits GenAI spans and metrics, and a cost computed from per-model pricing. You set the call rate (calls per minute), choose which models take part, and switch failure modes on and off.

Four failure switches

  1. Cost spike — runaway generation, roughly eight times the output tokens.
  2. Latency spike — about sixteen times the baseline latency.
  3. High error rate — about 25% of calls fail, against roughly 2% normally.
  4. Quality degradation — more hallucination and lower groundedness.

Each is independent, so you can test one alert at a time or combine them.

A test plan

  1. Start AI Observability at 30 calls a minute and confirm the token, cost and latency panels populate in your backend, split by model and provider.
  2. Build a cost panel: spend per model per hour from llm.cost.usd. Turn on the cost spike and check the budget alert fires.
  3. Build latency panels for time to first token and operation duration (p50 and p95). Turn on the latency spike and check which of them move.
  4. Alert on a falling groundedness score or a rising low-quality share. Turn on quality degradation.
  5. Alert on any prompt-injection or PII detection counter increasing.
  6. Run the Model Routing scenario and confirm you can see fallback behaviour split by gen_ai.request.model.
Synthetic, and marked as such. No real model is called and no real prompts are sent — the data is generated. It carries synth.generated: true like everything else, so keep it out of production cost reports by filtering on that attribute.
