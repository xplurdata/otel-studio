The 30 scenarios

Service flows and what each scenario is good for testing.

Each scenario simulates a real service topology. For every request OTel Studio produces a trace with 10–15 spans and correct parent-child links, one correlated log record for every service the request visits (so logs outnumber traces), and metric instruments recorded on every export cycle. Every service in a scenario is its own service.name. Logs carry the trace and span IDs of the span that was active when they were written.

Controls available on every scenario

ControlWhat it does
Interval, batch, error %How often a batch is sent, how many requests per batch, and what share of requests end in an error.
Geo / IP simulationAdds client.address and GeoIP-resolvable attributes — realistic regional ranges or RFC 5737 test ranges.
Synthetic PIIAdds user.id, user.name, user.email on reserved example domains, marked pii.synthetic: true, for testing redaction and DLP.
Custom attributesArbitrary key=value pairs added to the root span and logs — tag runs with a team, region or test ID.
Span duration overrideForce a minimum and maximum span duration.
Status code weightsFor example 200:90,404:5,500:5 to shape the HTTP status mix.
Sequential modeRotate through the enabled scenarios, one at a time, on a timer.
